ABSTRACT
Standard LLM inference suffers from a memory-bandwidth bottleneck due to sequential next-token prediction,
which limits real-world deployment. To address this, we first implement Set Block Decoding (SBD) in Pytorch, uti-
lizing a hybrid attention mechanism and joint training objective to prepare the model for parallel, non-contiguous
token generation at inference time. We validate that SBD training is stable and largely preserves autoregressive
performance on GPT-2 small. We then convert the fine-tuned weights to MiniTorch format and implement the full
inference pipeline from scratch, including the Entropy Bounded (EB) Sampler and KV-cache. End-to-end bench-
marking demonstrates up to3.56× fewer forward passes and2.67× wall-clock speedup. Code and models are avail-
able athttps://github.com/hailey-huyuhang/llmsys-project-set-block-decoding.
1 INTRODUCTION/ MOTIVATION
Standard LLM inference is severely hindered by the sequen-
tial nature of Next-Token Prediction (NTP), which requires
a full model forward pass to generate each individual token.
This creates a massive memory-bandwidth bottleneck, as
the GPU must repeatedly read the entire model’s weights
and KV-cache while performing very few floating-point
operations (FLOPs) per token.
The primary system challenge is to break this sequential
dependency without altering the underlying Transformer
architecture or adding auxiliary models. We must enable
the parallel sampling of non-contiguous future tokens while
maintaining compatibility with exact KV-caching and ensur-
ing that the model does not lose its foundational autoregres-
sive reasoning performance during the acceleration process.
In this work, we reimplement SBD (Gat et al., 2025) to
address these challenges. Our contributions span training,
inference, and benchmarking. We fine-tune GPT-2 small
on WikiText-2 using a hybrid attention mask and a joint
NTP+MATP loss, and validate that SBD training is stable
and preserves autoregressive performance. We then convert
the trained weights to MiniTorch format and implement
the full SBD inference pipeline from scratch, including the
hybrid inference mask, KV-cache, and Entropy Bounded
(EB) Sampler. Finally, we benchmark the system end-to-end
across block sizes k∈ {4,8,16} and entropy thresholds
γ∈ {3.5,6.0,10.0,16.0} , achieving up to 3.56× fewer
forward passes and 2.67× wall-clock speedup at k= 16 ,

2 RELATEDWORK/ BACKGROUND
Reducing the memory-bandwidth bottleneck of sequential
NTP has been a central focus of recent LLM inference re-
search. One central approach for accelerating this process
is speculative decoding, which utilizes a fast draft model
to generate candidate tokens for parallel verification by a
slower target model (Leviathan et al., 2023). Alternatively,
blockwise parallel decoding or multi-token prediction frame-
works attach additional decoding heads to the base model
itself to predict multiple independent tokens into the future
(Stern et al., 2018; Cai et al., 2024). However, in both cases,
the target model is generally restricted to verifying and ac-
cepting only a consecutive subsequence of these tokens,

and these methods often introduce significant architectural
modifications or system complexity. SBD requires no draft
model or extra heads, only fine-tuning the existing model
with a joint loss.

3.2 SBD Training Formulation
We address these questions by implementing Set Block
Decoding (SBD) (Gat et al., 2025), which enables parallel
token prediction through a hybrid attention mechanism and
a joint training objective.
• Hybrid Transformer Architecture: We de-
veloped a dual-purpose attention mask using
build sbd train mask dense(): standard
causal attention for historical tokens and bidirectional
attention for future prediction blocks, as illustrated in
Figure 3. Additionally, masked tokens are prevented
from attending to future clean tokens, ensuring
consistency with autoregressive constraints.

Masks
• Joint Training Loss: We implemented the joint
loss function L(x,ˆx;θ) =L NTP(x;θ) +L MATP(ˆx;θ),
which integrates Next-Token Prediction (NTP) and
Masked-Token Prediction (MATP) to ensure parallel

generation abilities without degrading foundational
autoregressive performance. The two objectives are
equally weighted via a single mean cross-entropy re-
duction over concatenated valid tokens. The masking
rate τ∼Uniform(0,1) is sampled independently per
sequence, following Algorithm 1 of (Gat et al., 2025).
Block length k is sampled uniformly from [2,16] per
step rather than fixed, so the model learns to decode
blocks of any size at inference time.
• Shared Positional Embeddings: Both
halves of the doubled input share position
indices 0, . . . , T−1 via position ids =
torch.arange(T).repeat(1, 2) , matching
the paper’s requirement that each token location
receives the same positional encoding regardless of
which half it appears in.
3.3 SBD Inference in MiniTorch
We implement the SBD inference pipeline in MiniTorch,
covering weight conversion, model modification, attention
masking, the EB Sampler, and a KV-cache decoding loop.
The key challenge is bridging the gap between the PyTorch
training environment and MiniTorch, since the two frame-
works use incompatible weight formats and operator sets.
We address this through a standalone conversion script and
a set of targeted modifications to the existing MiniTorch
DecoderLM.
• Weight Conversion: We implement
convert weights.pyto bridge the HuggingFace
and MiniTorch formats. The key challenge is that
GPT-2 stores Q, K, V as a single fused projection,
while MiniTorch DecoderLM expects three separate
weight matrices. We slice the fused tensor and save all
arrays as a.npzfile.
• MiniTorch Model Modification: We add an op-
tional mask parameter to MultiHeadAttention,
TransformerLayer, and DecoderLM. When

mask=None the behaviour is identical to the origi-
nal implementation; when provided, the mask is added
to the attention logits before softmax, injecting the
SBD attention pattern at inference time without any
architectural change.
• Inference Mask: build sbd inference mask
constructs a (1, H, Tfull, Tfull) additive mask where po-
sitions before causal point attend causally and
positions in the current block attend to all positions
(Figure 10 of the paper). Only the block rows are
passed to the model per forward call, keeping the shape
consistent withpast kvs.
• EB Sampler: entropy bounded sample com-
putes per-position entropy for all masked positions,
sorts ascending, and unmasks the largest prefix s such
that the cumulative entropy of positions 1, . . . , s−1
stays within γ. A larger γ allows more positions to be
unmasked per forward pass, reducing the total number
of forward passes needed to complete a block.
• KV-Cache and Decoding Loop: generate ntp
prefills the prompt once and decodes one token at
a time reusing cached K/V . generate sbd pre-
fills once, then calls sample block for each block.
Within sample block, the EB Sampler iterates until
all masked positions are revealed; a final forward pass
appends the completed block’s K/V to the cache for
the next block.

4 EXPERIMENTS
4.1 Experimental Setup
We use GPT-2 small (117M parameters) as the base model,
fine-tuned on WikiText-2. The GPT-2 tokenizer is extended
with a [MASK] token for masked prediction. Sequences
are chunked to T= 128 tokens. We train with AdamW
(lr = 3 ×10−4, batch size 8) for 34,000 steps. For SBD
training, block length k is sampled uniformly from [2,16]
per step, and the input is doubled by concatenating the
original sequence with a randomly masked copy, yielding a
2T -length input. We implement a 4D attention mask with
hybrid causal/bidirectional structure. All experiments are
conducted on a single NVIDIA Tesla V100-SXM2-32GB
GPU.
4.2 Baseline Training
We first validate the standard next-token prediction (NTP)
pipeline by training the model in autoregressive mode for
34,000 steps. The cross-entropy loss decreases from 3.99
at step 0 to approximately 0.63 at step 34,000 (Figure 6),
confirming that the training loop and data pipeline function
correctly. This serves as the reference for all subsequent
SBD comparisons.
4.3 SBD Training
We train SBD for 34,000 steps, logging the total loss Ltotal,
the NTP component LNTP, and the MATP componentLMATP
at each step. Results are shown in Figures 6, 7, and 8.
During training, we sample the block size k uniformly from
[2,16]to cover a range of prediction spans.
SBD training preserves NTP performance.The NTP
component converges to approximately 0.76 at 34,000 steps,
slightly above the baseline value of 0.63. This small gap is
consistent with the original paper’s observation that adding
the MATP objective results in only a slightly higher NTP
loss compared to standard NTP training.
The model learns masked prediction and continues to
converge. LMATP decreases from 9.3 at step 0 to approxi-
mately 3.1 at step 34,000, a reduction of 67%, with no sign
of plateauing. Ltotal decreases steadily from 6.2 to approxi-
mately 2.1 with no NaN values or loss explosions observed,
confirming that joint training is numerically stable.

5 ANALYSIS/ABLATIONS
5.1 Effect of Training Steps
Benchmarks for the 5,000-step and 34,000-step fixed block
size models produce nearly identical results, with NFE and
wall-clock speedup differing by no more than 0.02×under
the same configuration. This suggests that on WikiText-2,
the prediction entropy distribution of GPT-2 small stabilizes
after roughly 5,000 steps and changes little with further
training. We attribute this to the small size of the dataset:
with only approximately 2M tokens, the model approaches
overfitting within a few epochs, and additional training steps
primarily re-expose the model to the same data rather than
improving MATP capability.
Figure 12. Wall-clock speedup at 5,000 and 34,000 training steps
under fixed block size (k= 8) acrossγvalues.
5.2 Effect of KV-Cache
Without KV-cache, we benchmark a 5,000-step fixed block
size model with k= 4 and γ∈ {0.1,0.35,0.6} . NFE
speedup is only 1.07 × across all γ values, because with
k= 4 and small γ, the EB-Sampler unmasks only one to-
ken per step, leaving almost no room for parallel decoding.
Beyond the limited NFE reduction, the absence of KV-cache
means prompt tokens are recomputed in every forward pass,
so even the small NFE saving does not translate to mean-
ingful wall-clock speedup. The original paper states that
SBD maintains compatibility with exact KV-caching, there-
fore we implement a numpy-based KV-cache in MiniTorch,
managing historical K and V via np.concatenate and
correcting position embeddings through an offset param-
eter. After adding KV-cache, NFE speedup reaches up to
2.67× at γ= 10.0 with k= 8 , as shown in Figure 13. This
confirms that KV-cache is a necessary condition for SBD
acceleration.

5.3 Effect of Variable Block Size
Compared to fixed block length training with k= 4 , sam-
pling k uniformly from [2,16] results in lower MATP loss
at the same number of training steps, as shown in Figure 9.
This suggests that exposing the model to different prediction
spans during training improves convergence.
5.4 Entropy Distribution and Block Size
The entropy threshold γ needs to be calibrated to the model
and training setup. The original paper reports much smaller
γ values than the ones used in our benchmark. In contrast,
our GPT-2 small model produces block-token entropies
between 3.16 and 7.18 nats in our probing experiments.
When we apply the paper’s smaller γ values directly, the
EB-Sampler often unmasks only one token per step, yielding
little or no speedup. This motivates sweeping a larger range
ofγ∈ {3.5,6.0,10.0,16.0}for our model.
One possible explanation is the difference in model and
training scale. The paper evaluates larger models, such as
Llama-3.1 8B and Qwen-3 8B, while our experiments use
GPT-2 small trained on WikiText-2. A smaller model may
be less confident when predicting multiple future tokens in
parallel, so larger γ values are needed to trigger multi-token
unmasking. Since we do not evaluate the paper’s models
under the same setup, this should be viewed as a possible
explanation rather than a direct comparison.

5.6 Conclusion/Discussion
We implemented and evaluated SBD across both training
and inference in GPT-2-small setting. On the training side,
we fine-tuned GPT-2 with both the autoregressive loss and
the masked parallel prediction loss. The training curves
show that SBD can learn the masked prediction objective
while preserving similar autoregressive training behavior to
the baseline. On the inference side, we built a MiniTorch im-
plementation of SBD decoding, including the SBD attention
mask, entropy-bounded sampling, and KV-cache support.
The main takeaway is that SBD can reduce forward eval-
uations and also bring real inference speedup. In our best
setting, with block size 16 and gamma 10, SBD achieves
2.91x NFE speedup and 2.30x wall-clock speedup, even
with system overhead. Compared with a more optimized
PyTorch or CUDA-based implementation, our MiniTorch
implementation has extra overhead from sources such as
Python control flow, MiniTorch tensor operations, and KV-
cache concatenation. These costs likely explain part of the
gap between NFE speedup and wall-clock speedup.
Another limitation is generation quality. Although SBD

gives clear speedup, its PPL is still much higher than the
NTP baseline in our experiments. In the best setting dis-
cussed above, SBD has a PPL of 96.5, compared with 1.67
for the NTP baseline. We also use much larger gamma
values than those reported in the paper. This may be re-
lated to our use of GPT-2 small and a smaller training setup,
which could make the model less confident when predicting
multiple future tokens in parallel.
For future work, we would like to address both limitations.
On the system side, customized CUDA kernels for KV-
cache updates could reduce overhead and make wall-clock
speedup closer to NFE speedup. On the model side, scaling
to larger datasets, training for more steps, and testing larger
models would make the evaluation more comparable to the
paper and help us better study the speed-quality tradeoff.
